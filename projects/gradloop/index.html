FOUR CHAPTERS · ONE SYSTEM

不仅介绍功能，
也打开实现。

本页建立系统全貌，后三章分别深入数据、执行与模型。每章都有实际机制、源码入口和验证边界。

GradLoop 的全名是 GradLoop RAGSDK Omni，中文名“研循”。它面向课程学习、面试与答辩准备：先让资料成为可追溯证据，再把问答转成计划、练习、反馈与复习。这里的 Omni 指多模态方向；4.5 是 MiniCPM-o 的模型版本，不是项目名中的版本号。

项目的重点并不是让一个模型自由调用所有工具，而是把知识摄取、检索接口、业务状态和人工确认拆开，使每一步能定位来源、理解副作用，并单独验证。公开站点是合成素材回放；本地应用代码、模型实验记录与当前在线能力是三种不同证据。

SYSTEM ARCHITECTURE

六层职责，
一条可追溯链路。

可替换的检索后端与有界业务工具分开。模型是可选能力，学习状态不是聊天记录的附属品。

01 · 交互与 API

静态学习工作区连接 FastAPI 的问答、计划、练习与 Agent 接口。SSE 暴露节点执行进度；文档模式另在浏览器 Worker 中提取文字，不能与后端知识入库混为一谈。

02 · 知识摄取

输入先过路径和格式门禁，再解析、扫描隐私、脱敏、分块与发布。片段保留 source_id、chunk_id、章节和页码；generic / personal 分区控制可检索范围。

03 · 统一检索契约

RagBackend 统一索引、删除、检索、问答和健康信息。BM25 提供不依赖模型的词法基线；RAGSDK 适配 dense / sparse / hybrid / hybrid_rerank，显式选择后端而不静默冒充。

04 · 有界执行图

LangGraph 按规则分流到固定工具，检索不足最多重试一次，工具步骤受上限约束。计划调整进入 interrupt；用户接受后才写入，checkpoint 支持从保存位置恢复。

05 · 学习业务状态

LearningService 与 SQLite 保存画像、计划、题目、作答、错题及调整提案。连续练习围绕同一错题 ID 推进，跨请求保留反馈；评分与复习规则保持可解释。

06 · 模型与验证

Qwen 本地文本生成和 LLM 批改复核是可选旁路；MiniCPM-o 承担多模态方向。独立实验仓管理来源、冻结样本与 Base / LoRA 对照，不把 smoke 当作质量提升。

典型问答请求怎样穿过这些层？

HTTP 请求 → Agent 意图路由 → search_knowledge → LearningService → RagBackend → 来源片段；如配置 LLM，再将带标号的证据上下文送入生成，最后返回答案、引用、后端身份与运行 trace。没有启用生成模型时，baseline 明确返回证据摘录。

运行时装配：build_runtime · 检索抽象：RagBackend · 执行图：_build_graph

THE LEARNING LOOP

从资料，到下一步练习。

围绕资料、问答与练习组织学习过程。
让知识有来源，让行动能解释。

01 / STUDY

学懂，而不只是看过。

从检索与带来源的问答开始，再拆成学习计划、练习和错题复习。知识与练习沿用同一条证据链。

02 / INTERVIEW

把回答，变成反馈。

围绕专业解释与面试表达记录结构化反馈，再进入下一轮练习。评分实验与真实用户效果分开记录。

03 / CONTROL

能继续，也能停下来。

用 LangGraph checkpoint 与 interrupt/resume 保存本地工作流状态。计划调整由用户确认，不静默替人决定。

LOCAL-FIRST WORKFLOW

一次问答，
是闭环的开始。

资料、回答、练习与复习不是孤立的入口。本地工作流将它们串起来，并在需要用户决策时停下来。这是跨请求的业务状态闭环，不是一次调用全自动学完课程。

深入学习状态与复习规则
  1. 01

    资料问答

    检索候选片段，以证据约束提示生成回答；引用可回溯，但尚未逐句验证语义正确性。

  2. 02

    计划与练习

    连接学习目标、练习任务与确定性评分基线。

  3. 03

    批改与复习

    保留同一条错题记录，按通过条件进入复习与掌握状态。

  4. 04

    确认与恢复

    有界重试；人工确认计划调整；本地恢复点支持继续执行。
