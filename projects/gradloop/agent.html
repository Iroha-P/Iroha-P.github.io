BOUNDED AGENT · STATEFUL LEARNING

让学习动作
有状态，也有边界。

GradLoop 用真实 LangGraph 状态图连接类型化工具，把重试、人工决策和恢复位置写进执行机制。这里沿源码拆解一次请求如何推进，以及计划、批改和错题如何跨请求组成闭环：哪些状态可以恢复，哪些副作用仍需谨慎，哪些指标只证明测试契约。

01 / CONTROL FLOW

先限定动作，再让流程推进。

这里的 Agent 是有界业务编排，不是拥有任意工具的自主规划器。

七类意图，规则路由

请求包含 user_id、可选 intent、message 与 payload。route_intent 优先使用明确 intent；未提供时按“计划、练习、批改、重答、错题、确认调整”等关键词分类，其余归入 ask。输入落到固定业务动作，而不是由模型临时创造执行路径。

一次检索重试，八步工具上限

问答把“有非空引用且有非空回答”视为证据足够。否则进入 retry_search，追加固定查询词，并将 Top-K 扩大到最多 20；retry_count 达到 1 即结束。每次工具调用先检查 step_count，LangGraph 最多八步；它不是八个图节点的限制。

显式 baseline 保留六步上限，和 LangGraph 共用 LearningTools、LearningService 与学习数据库。这样可以比较编排层的恢复和中断能力，不把更换底层题库或评分器造成的差异算成 Agent 收益。固定重试也容易审计，但不能称为 LLM 查询规划；“有引用”更不能直接证明回答语义正确。

源码依据：LearningAgent / _classify、_call_tool / _search / _route_after_search。

02 / THE ACTUAL GRAPH

十一节点，不是一张概念图。

按 _build_graph 的实际名称与边整理；START 和 END 是图边界，不计入十一节点。

展开精确节点与条件边清单 
START → route_intent
  ask      → search_knowledge
                 ├─ 证据足够 → finalize
                 └─ 证据不足 → retry_search → finalize
  plan     → create_study_plan      → finalize
  practice → get_practice_questions → finalize
  grade    → grade_answer
                 ├─ 无 revision_id → finalize
                 └─ 有 revision_id → await_revision_decision
                                        interrupt / resume
                                        → finalize
  mistakes → list_mistakes          → finalize
  redo     → redo_mistake           → finalize
  revision → decide_plan_revision   → finalize
finalize → END

业务动作与图节点分层

grade_answer 内部调用业务服务，已经完成评分、错题保存和调整提案生成；图中没有单独的“质量检查”或“保存错题”节点。是否进入确认分支只检查 revision_id。避免把概念架构图中的阶段当成额外实现，可以准确解释哪些操作发生在同一次工具调用内。

一次请求只走一个业务分支

plan 不会自动继续出题，practice 也不会替用户作答。图负责当前动作，SQLite 负责连接不同请求的学习状态。由此保留用户参与和可检查的中间结果，而不是把完整学习过程藏进一轮长执行。

源码依据：LangGraphLearningAgent._build_graph、_grade_answer。

03 / INTERRUPT & RECOVERY

暂停的是执行，不是用户决定权。

重要调整先形成提案；恢复点与运行原文分开存放。

interrupt：先等确认，再写计划

批改生成 revision_id 后，await_revision_decision 用 interrupt 返回动作类型、trace_id 和提案 ID。运行状态变为 waiting_for_confirmation。用户调用 resume 提交 confirm，图通过 Command(resume=…) 继续；接受才替换计划任务，拒绝只更新提案状态，不静默改变学习安排。

thread_id 就是 trace_id

每次运行使用 trace_id 作为公开运行标识，也将它映射到 LangGraph 的 configurable.thread_id；没有另一套独立 run_id。状态查询和恢复先核对用户摘要归属。人工中断只需确认决定；故障恢复需要重新提交原请求，因为恢复点不保存它。

持久化执行状态
意图、scope、当前节点、步骤与重试计数、revision_id、pending_action、恢复计数和错误类型。
摘要而非正文
用户 ID 散列；输入键名、文本长度和摘要散列；输出对象 ID、分数与列表数量。
只在当前运行传递
AgentRunContext 接收原请求、结果容器和工具轨迹，不作为图 state 写入 checkpoint。

不进 checkpoint，不等于不落地

SqliteSaver 保存恢复点，学习数据库则保存脱敏后的作答、评分和错题。两者职责不同。get_status 返回执行位置而非原回答归档；这套用户归属核对也不应被包装为完整的身份认证系统。

源码依据：AgentGraphState / build_checkpoint_seed、interrupt / thread_id 映射、resume / get_status、save_attempt。

04 / TYPED TOOLS

固定工具，明确副作用。

工具不暴露任意文件操作或 shell；业务输入通过 Pydantic 模型校验。

LearningTools 的七个工具及其业务读写边界
工具输入与作用业务状态变化
search_knowledge问题、Top-K、scope；默认 generic检索与回答；编排层另记摘要轨迹
create_study_plan目标、期限、时长、弱项保存计划与用户画像
get_practice_questions主题、难度、数量、scope检索题库或生成模板题，保存题目
grade_answer题目 ID、用户作答保存作答；低分可写错题、弱项和提案
list_mistakes用户、状态、主题、数量查询该用户错题
redo_mistake错题 ID、题目 ID、新作答保存新作答，更新原错题
decide_plan_revision提案 ID、确认决定更新提案；接受时更新计划

用户与能力边界分别处理

工具 wrapper 用当前请求的 user_id 覆盖 payload 中同名值，再交给业务模型。数据库按用户核对对象归属。没有任意执行工具能够缩小操作面，但底层服务仍会读写 SQLite，不能把“无 shell 工具”称作完整安全沙箱。

局部幂等，不承诺全部 exactly-once

题目 INSERT OR IGNORE，计划、错题和提案按对象 ID upsert，轨迹以 trace_id 与 sequence 为主键；已处理的 revision 再提交不会重新应用。但 grade 每次新建作答 UUID，多个保存调用与 checkpoint 不在同一个原子事务。节点恢复有助于减少重复执行，仍不能证明崩溃窗口下所有副作用恰好一次。

源码依据：LearningTools、对象保存与用户归属、提案与轨迹主键、decide_revision。

05 / ACROSS REQUESTS

学习闭环，靠状态连接。

一份计划、一组题目、一次作答和原错题 ID，构成能够追踪的跨请求关系。

  1. 01

    7 / 14 / 30 天：时间预算先于排课

    计划从每周时长折算总分钟，按轻量、平衡或强化系数分配，围绕弱项轮换诊断、精读、练习和模拟。任务包含期限、分钟数、来源与产出物；校验总时长、截止日期和最后一天复盘。这是可检查的规则模板，不是已证明最优的学习策略。

  2. 02

    出题：题库优先，证据不足就停下

    先按主题、方向、难度和 scope 选择派生题库。无匹配时检索资料，以带来源 ID 与 chunk ID 的结构化模板生成练习；检索为空则返回空题集与警告。模板不会被称为自由生成、已通过事实校验的完整题库。

  3. 03

    反馈：错题与计划提案分开

    低分保存错题并累积弱项；存在可替换的待办任务时，生成补强提案，保留复习与模拟任务。提案本身不会改变计划，用户确认后才应用。后续重答继续更新同一错题，使版本与复习状态可以追踪。

源码依据：StudyPlanRequest.days、create_plan / _validate_plan、get_questions、_propose_revision。

06 / GRADING POLICY

分数要解释，掌握要复习。

规则评分负责当前决策，LLM 负责旁路复核，两者的职责不混写。

五维确定性基线

默认量表分为清晰度、覆盖、推理、证据和反思。实现使用回答长度与表达信号，而非完整语义判断；低于 80 分进入错题链。它可复现，但存在关键词投机和尺度偏差风险，不能把规则高分等同于事实正确。

LLM 旁路：严格结构，保留分差

可选复核要求 JSON schema、维度集合完整、无重复且不超单维满分，结构失败后最多重试一次。输出包含 score_delta、理由、改写与置信度；不可用时保留基线。校准前模型分不参与错题、掌握或计划决策，confidence 也不是回答正确率。

80 分、连续两次、1 / 3 / 14 天

首次错题默认两天后复习。重答低于 80 分时连续通过计数清零，回到 open，一天后再答；首次达标进入 reviewing，三天后重答；连续两次达标进入 mastered，十四天后保持性复习。每次增加 answer_version 和 redo_count，沿用原 mistake_id。“已掌握”只是应用内规则状态，不能推断真实认知提升。

源码依据：grade / _score_dimensions、StructuredLlmGrader.review、首次复习日期、redo_mistake。

07 / API & OBSERVABILITY

进度真实增量，容量明确拒绝。

可靠性不仅是正常返回，还包括忙时行为、错误信息和资源释放。

共享门控与 429

FastAPI 的 ask、Agent 同步执行、恢复与 SSE 共用 ExpensiveOperationGate。BoundedSemaphore 非阻塞获取，默认两路；满额立即返回 429 capacity_exhausted，附 Retry-After、request_id 和 trace_id。它是进程内并发保护，不是跨 worker 分布式限流，也不是线上吞吐测量。

start / node / tool / done / error

SSE 直接消费 graph.stream(stream_mode="updates")，节点推进时发 node，工具完成时发名称、序号与状态，最后给出完成或等待确认状态。它没有先同步执行再回放，也不是模型 token 流；事件不携带答案正文。HTTP 错误与图异常仅暴露安全码或异常类型，便于关联问题而不回传原片段。

释放配额，不等于取消推理

流生成器的 finally 释放门控；公开后端没有 Agent cancel 端点或贯穿图与模型的取消令牌。因此只能说明流结束后的清理机制，不能承诺断线会立即终止在途同步调用。失败后的状态查询与恢复也不等于自动重连或自动继续。

源码依据：ExpensiveOperationGate、请求关联与错误处理、Agent API / SSE finally、真实 graph.stream 事件。

08 / EVIDENCE LEVELS

测了什么，比数字更重要。

应用执行、合成工具编排和 fixture 一致性，是三种不同证据。

集成测试覆盖真实业务调用

公开测试使用临时 SQLite 与 BM25 合成片段，覆盖计划、出题、低分批改、确认提案和错题记录；还检查 interrupt 后查询 next_nodes、resume 完成、其他用户访问返回 403，以及重答保持同一错题 ID。本页是源码讲解，没有重新运行这些测试，不将测试存在写成此次执行通过。

工作流 evaluator 与 108 条组合报告

evaluate_agent_cases 确实创建 LangGraph，配合合成工具和故障注入，检查工具顺序、中断、恢复、重复调用及 checkpoint canary 泄露；范围限定 workflow_only_public_synthetic。另一份 108 条公开组合报告中，Agent、计划与批改属于 fixture_consistency，只比对确定性契约，不执行应用 Agent。其 1.0 不能表述为真实 Agent 成功率。

历史验收不等于当前在线能力

2026-07-23 的 CPU Docker 聚合报告记录了 BM25 + LangGraph + SQLite 与 SSE 链路通过，未调用语言模型。公开网页的学习模块则使用合成回放，不连接这里的真实学习数据库。页面所有实现依据固定公开 SHA；本地开发分支、历史运行证据与在线部署状态分别陈述。

下一章进入模型与评测：理解模型协议、历史 Ascend 实验和人工评分证据，为什么不能由“运行成功”直接推导“质量提升”。

源码依据：业务闭环 / interrupt / 重答测试、evaluate_agent_cases、fixture_consistency 边界、历史 CPU / SSE 验收、公开 Demo 回放范围。
