KNOWLEDGE & EVIDENCE

让材料成为证据，
让检索保持可解释。

知识库不是把文件交给模型就结束。GradLoop 先检查来源与隐私，再保留分块、分区和引用身份，最后连接可替换的检索后端。这里沿公开源码解释材料如何进入问答与题库，也说明召回、拒答和生成验证之间尚未闭合的边界。

01 / DATA CONTRACT

先统一证据身份，再替换检索实现。

同一份业务请求可以切换后端；
结果仍要说明资料来自哪里。

输入不是裸文本，而是带定位的知识片段

DocumentInput 为每个片段保存 source_id、chunk_id 与正文，并携带标题、章节、页码、发布日期、权威级别和 metadata。Pydantic 合约禁止额外字段，避免接口悄悄接受拼错或未约定的数据；页码与日期允许为空，所以“可以追溯”不等于“每份来源都有完整日期”。

检索、回答和生成身份分开表达

RetrievalRequest 默认 Top-K 为 5、scope 为 generic；结果保留候选正文、分数、检索类型以及分阶段耗时。AnswerResult 再补充引用、拒答状态和 warnings，并把检索 backend/version 与生成 backend/model、llm_called 分开。这样 BM25 命中资料与模型生成回答不会共用一个含糊的“成功”标签。

DocumentInput → index / delete / retrieve / answer
RetrievalResult → documents + backend + trace_id + stages
AnswerResult → answer + citations + abstained
             + generation_backend + generator_model + llm_called

源码依据：base.py · 数据模型 · RagBackend · 六个统一入口

02 / PRIVACY-GATED INGESTION

摄取的第一步，是决定什么不能进入。

先授权与检查，后解析与分块。
原始材料不直接成为检索输入。

  1. 01

    校验来源路径与格式

    authorize_file 拒绝越出授权根目录、路径穿越、UNC/device 路径及直接符号链接；默认只接收不超过 50 MiB 的 MD、TXT、PDF、DOCX，并检查 PDF 签名与 DOCX 容器必需成员。扩展名不是唯一通行证。

  2. 02

    扫描敏感度，再决定确认或拒绝

    规则扫描联系方式、身份字段、secret、风险路径词及部分提示注入表达，取声明与扫描中的较高敏感度。高敏默认拒绝，中敏或可疑注入进入脱敏预览与确认；公开摄取模式只接受 public 且没有注入标记的内容。这是规则式闸门，不宣称识别所有个人信息。

  3. 03

    脱敏后生成稳定片段

    默认按 800 字符、120 字符重叠切分，优先句号或换行；同次构建按正文 SHA-256 去重。chunk_id 结合来源、源文件哈希、位置、正文和分块版本生成，保留章节与页码，便于判断内容或解析策略发生了什么变化。

结构信息与构建版本一并保存

Markdown 标题成为章节，DOCX 提取段落与表格，PDF 只读取文字层并保留页码，不自动 OCR。Manifest 记录 checksum、parser/chunker 版本、隐私摘要和摄取状态；只有这些版本与文件内容均未变化且旧状态已入库，才复用旧分块。单文件写入采用临时文件、fsync 与原子替换，但这本身不是整个摄取过程的多文件事务。

源码依据：authorize_file · scan_privacy / decide_ingestion · build_chunks · IngestionPipeline.ingest

03 / SCOPED KNOWLEDGE

通用知识与个人叙事，不默认混检。

分区约束进入数据文件与检索过程，
而不只写在提示词里。

generic / personal / all

派生语料按 generic 与 personal 物理分文件。加载时校验每个文件的 privacy_lane，并检查跨文件 chunk_id 唯一；查询默认 generic，只有显式 all 才跨分区。BM25 先确定可检索文档，再计算该分区的词频统计与平均长度，个人语料不会参与通用查询的排序统计。

飞书只读快照，而非远端写入

客户端仅允许认证状态、空间列表、节点列表和 Docx fetch，并验证用户身份与只读权限。同步遍历全部节点，在 staging 生成完整 inventory；重复节点、读取失败或隐私拒绝会中止发布，通过后才替换 current，替换异常可恢复旧快照。

匿名来源 ID，不等于删除全部远端身份

飞书来源 ID 由 node token 哈希生成，未知目录保守归入 personal；本地快照仍需保存 revision、远端 token 和节点路径来维护同步关系，不能把“匿名 ID”说成完全没有敏感元数据。公开仓提供同步代码与合成资料，不包含用户运行快照；公开启动器还会覆盖语料和状态路径，隔离已有个人索引。

源码依据：load_scoped_corpus · SnapshotManifest / lane / 原子发布 · SnapshotSyncService.sync · 只读命令与认证校验

04 / EVIDENCE-DERIVED PRACTICE

题目从证据派生，不靠模型自由补答案。

抽取、归并与复核分别记录，
不把缺失信息伪装成完整题库。

规则抽取候选，来源引用跟随题目

抽取器识别 Markdown 问答表、编号题、问号与问题语境，把候选题干和相邻答案证据绑定到 source_id、章节、页码和 revision。没有答案证据的题目标记 needs_answer，而不是让模型补一个“看起来合理”的答案。最终 QuestionRecord 保留 source_refs、内容指纹、重复组、隐私 lane 与审核状态。

先精确归并，再谨慎处理近似题

精确去重按 lane 与规范化题干分组，跨分区不合并。近似候选使用字符 3-gram 与 2-gram Jaccard，达到 0.82 / 0.75 才进入复核；配置模型复核时，只有语义等价且置信度不低于 0.85 才合并。答案证据版本不同会保留 conflict；数据集可按 duplicate_group 划分，避免同一组题同时进入开发与测试。

LLM 输出可拒绝，发布前再校验一次

辅助分类要求严格 JSON，最多尝试两次；answer_points 与 evidence_quotes 必须逐字存在于输入证据，否则退回 needs_review。字符串包含检查不能证明推理正确，但能限制越界改写。题库先在 staging 写入题目、冲突、覆盖统计与分区语料，全部合约通过后整体切换；API 默认只选 accepted 题目。

源码依据：_make_candidate · canonicalize_questions / 按组划分 · QuestionEnricher.enrich · QuestionBankBuilder._publish

05 / RANKING & BOUNDARY GATES

命中相似词，不代表问题已有答案。

排序解决“先看什么”，
证据门控解决“是否继续生成”。

无模型 BM25：透明的对照基线

基线索引标题、章节与正文；英文数字按正则分词，中文加入单字、相邻双字及短整串。使用 k1=1.5、b=0.75，保留正分候选，按分数降序与 chunk_id 稳定排序后截 Top-K。默认 answer 只在没有命中时拒答；有命中就展示原片段，并明确没有调用大模型。因此它是词法与工程对照，不是语义回答器。

Top-1 与 Composite：显式选择的实验策略

Top-1 Gate 启用后比较首条分数与阈值，无文档或低于阈值就拒答，并在 LLM 调用前结束。Composite 再利用 Top1/Top2、归一化 margin、单文档与 Top5 联合覆盖、数字和英文 anchor 覆盖；协议限定 baseline/bm25-v1/Top-5，候选不足两条、分数无效或次序异常时保守拒绝。组合阈值需要同时满足覆盖和 Top1 条件，再由 margin 或高覆盖 override 放行。

生成前约束与生成后验证，是两件事

配置 LLM 时，LearningService 将最多约 12,000 字符上下文标为 [S1] 等来源，提示模型只依据资料，再附上传入上下文的引用元数据。当前实现直接返回 generated.content，没有逐句引用核验或语义蕴含检查；引用列表不能证明每条回答均被资料支持，日期字段也不自动构成时效判断。

三种决策策略：默认行为与实验能力分别陈述
策略何时拒绝继续默认运行时状态
BM25 基线回答没有检索命中；有命中时展示原片段基线支持；不调用大模型
Top-1 Gate没有文档，或首条分数低于配置阈值可选策略；未接入默认装配
Composite Gate候选或分数异常，或覆盖、Top1 与 margin 条件不足实验策略；限定 BM25 / Top-5 协议

门控未接入默认运行时

EvidenceGatePolicy 默认 disabled；build_runtime 创建 LearningService 时没有传入 evidence_gate_policy。可选门控与实验代码已经存在，但不能写成默认产品已部署，也不能把检索高召回当作可靠拒答的证据。

源码依据：tokenize / Bm25BaselineBackend.retrieve · Top-1 Gate · Composite 特征与决策 · LearningService.ask · 默认服务装配

06 / EXPLICIT RAGSDK ADAPTERS

四条检索路径，共用可核查的后端边界。

适配实现、依赖就绪与真实运行，
分别表达，不互相替代。

保留应用分块，不把原件交给 SDK

Native 适配使用 TEIEmbedding、MilvusDB、开启 BM25 的 MilvusDocstore 和 KnowledgeDB。索引按 source_id 归组，生成安全 staging 文件名，通过 KnowledgeDB.add_file 传入预分块正文、dense embedding 函数和来源 metadata；KnowledgeDB 的 white_paths 限定 staging。旧架构文档中的 LoaderMng/upload_files 是设计链，当前源码以 add_file 为准。

RAGSDK 检索模式及适配中真实调用的组件
模式候选与排序链输出轨迹
DenseRetriever + TEI dense embeddingdense
SparseFullTextRetriever + BM25 docstoresparse
Hybrid两路召回 → MixRetrieveReranker 融合dense / sparse / fusion
Hybrid + rerank融合候选 → TEI reranker → Top-K再增加 rerank

候选参数与能力限制明确暴露

混合模式默认 dense、sparse、fusion 候选上限均为 20；精排要求返回分数数量与候选数量一致，按分数排序后截 Top-K。当前融合调用的是 SDK 的 MixRetrieveReranker，不是项目自研 RRF。RAGSDK 只开放 generic scope，personal/all 需另行配置隔离集合；filters 只接受 document_id，原生生成链只支持 Dense 并已配置 LLM 的情况。

缺依赖就失败，不用 BM25 冒充 RAGSDK

factory 只创建配置对应的后端；Linux、Python 3.11、mx_rag、pymilvus 与服务配置不满足时返回 backend_unavailable，不静默降级。Native 的 runtime_verified 必须同时有索引与检索执行记录；矩阵合约禁止 not_run/failed 携带效果指标。当前公开证据不足以证明真实 RAGSDK 全链路运行，四路代码存在也不等于四路效果已测量。

源码依据：NativeRagsdkRuntime.create · index_documents / add_file · retrieve / generate · scope 与生成边界 · 矩阵状态合约

07 / MEASURE WHAT ACTUALLY RAN

把高召回与拒答失败，一起留下来。

108 条公开案例不是同一种证据。
先看测了什么，再看数字。

真正执行的检索组：召回好，边界仍弱

public-synthetic-portfolio-v1 使用 20 个合成片段。40 条检索问题中，32 条可回答、8 条不可回答；BM25 Recall@5 为 0.96875、MRR 为 1.0、nDCG@5 为 0.971969，但 no-answer 指标为 0.0。该指标判断不可回答问题是否没有检索结果，说明这 8 条仍命中了内容；它不是生成语义拒答率，更不能把 Recall 改称问答准确率。

fixture 检查与运行验收，不混成一个通过率

回答 fixture 直接读取预设 answer、citations 和 abstained；Agent 组比较预期工具序列与状态，评分组使用评测内部公式。因此这些结果只验证固定合约，不证明逐句事实正确性、真实 Agent 成功率或实际批改质量。另有 2026-07-23 CPU 容器报告保留真实 BM25 + LangGraph 问答与 SSE 验收，但明确 llm_called=false，也不是 RAGSDK 运行证据。

公开版本与后续实验，保持可追溯

本页源码固定到应用仓 ad9aafdd，而不是滚动 main。公开树保留部分边界实验代码与数据，但未保留相应完整运行报告，不能把本地分支指标补成公开成效。下一步价值在于用独立协议验证拒答、引用与生成，而不是只优化一个召回数字；模型与人工量表实验在下一章继续区分。
