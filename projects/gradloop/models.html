TWO REPOSITORIES, DISTINCT RESPONSIBILITIES

应用与模型工程，分别交付。

应用可以独立运行。
使用学习产品，不等于必须训练模型。

gradloop-ragsdk-omni 管理 API、RAG、Agent、界面与学习状态；gradloop-ragsdk-omni-training 管理来源策略、合成数据、冻结评测、NPU 实验和模型服务。分仓隔离了重型计算依赖与应用发布节奏，但不自动保证协议一致。本页按 2026-10-10 核验的公开 main 编写：应用版本 ad9aafdd79e4、Training 版本 0364c69f5a91；来源链接固定到完整提交。

本地 Qwen：文字与复核

默认配置名为 qwen3-4b-q4，通过仅允许回环地址的 llama.cpp 客户端生成证据内回答。结构化批改是旁路建议：校验 JSON、量表和分差，最多尝试两次；确定性评分仍决定错题与计划状态。

MiniCPM-o：媒体理解

MiniCPM-o 4.5 作为独立多模态后端，承担图像、音频等材料理解。Training 保存 Ascend Base / LoRA 的实验流程，不把训练步骤塞进业务 API，也不要求应用随附权重。

MAP：可选文字会话

浏览器经 Worker 代理连接 MAP。文档模式可以把用户确认后的正文作为文字输入；本地解析不依赖这个连接。代理地址存在、会话就绪与一次推理成功，是不同状态。

源码依据：双模型配置 · StructuredLlmGrader.review · 双仓职责

DATA CONTRACT & SOURCE-CONNECTED SPLITS

先证明数据从哪里来。

来源、证据和生成配方可关联，
才有资格进入实验流程。

不是一个文本文件，而是一组可校验的关系

TrainingSample 同时携带场景、任务、prompt、参考答案、rubric，以及 source_ids、evidence_ids、provenance_ids。公开来源的 provenance 保存内容 SHA-256、UTC 获取时间、许可证和允许用途；合成来源保存 recipe 名称、版本与哈希。构建器要求样本的 provenance 集合精确等于其来源对应的身份集合，证据字典也必须与实际引用完全匹配，拒绝缺项和未引用内容。

许可闸门默认拒绝，不把“公开可见”当许可

来源策略检查 HTTPS 公网地址、许可证 URL、用途、署名和声明的访问限制；未知许可、登录或付费来源被拒绝。model_training 必须被显式允许，当前策略中的 CC-BY-SA-4.0 不具备该用途。采集器还要求显式注入 fetcher，默认不抓取。它检查的是声明与策略的一致性，不能替代人工许可审查或外部法律核验。

来源关联划分：把共享来源留在同一侧

assign_source_connected_splits 用并查集连接共享来源，再对排序后的来源组件与 salt 做 SHA-256 分桶：80 个桶用于 train、10 个用于 validation、10 个用于 test。这是组件级确定性规则，不保证小样本恰好按 8:1:1 分配。随后逐来源验证没有跨 split 泄漏；冻结评测只从 test 派生，避免同源材料同时用于训练与测试。

源码依据：来源与 recipe manifest · 证据、provenance 与 test 关联 · 来源组件划分 · 来源策略与显式采集

STAGE A · SYNTHETIC FOUNDATION

合成数据，验证流程而非效果。

能构建、能拒绝、能冻结，
先于“模型是否更好”。

推荐构建规模
60 条合成样本
场景覆盖
课程 / 技术面试 / 科研答辩
冻结 test
5 条 · 拒答支持 3 / 2
媒体 sidecar
60 个 · 不含二进制媒体

sidecar 是媒体描述，不是训练过真实多模态数据

Stage A 每场景推荐 20 条确定性样本，包含 document、image、audio sidecar 中的 OCR、transcript 或 metadata 文本，用来验证 schema 和扫描覆盖。冻结集必须非空、覆盖三个场景，并同时存在应拒答与不应拒答案例；当前 recipe 与 salt 下每场景 17 条是首次满足这些条件的数量。不能把这些 fixture 写成真实用户数据或生产级多模态训练集。

发布前扫描，失败不产生半成品

闸门扫描 prompt、参考答案、rubric、追问、sidecar 与全部引用证据，检查个人信息模式、凭据和本机路径。近似复制检查将中文字符及英文词元归一化，以带重叠的有界分块查找连续复制片段；这是启发式检查，不是语义查重。finding 只保留安全 ID、字段和原因码。全部校验通过后才用临时目录原子发布，已有目标目录不合并、不覆盖。

源码依据：Stage A 数量与评测条件 · 近似复制与隐私扫描 · 冻结后置条件与原子发布

NARROW SERVICE · CONTRACT BEFORE CONNECTIVITY

窄服务要严格，兼容性要实查。

相同端点名称，
不代表请求和健康协议相同。

Training 服务只接受已声明的输入

parse_generate_request 要求 content_policy=public_or_synthetic，prompt 最多 4,000 字符；最多两个附件，单个解码后 2 MiB、合计 3 MiB；图片为 JPEG / PNG / WebP，音频仅 WAV，max_new_tokens 默认 128、上限 256。不接受文件路径、原文件名或身份字段，也不支持 video。图片经 BytesIO 转 RGB，音频转为 16 kHz 单声道；Base 从既有缓存加载，关闭 TTS，非流式返回，不提供训练端点。

当前公开双仓契约不直接兼容

应用客户端与 Training 窄服务虽然都使用 /v1/omni/generate，字段却没有对齐。严格服务会拒绝多余字段，应用也不会把服务的 status=ready 识别为就绪。修复需要显式版本化适配和契约测试，不能把它描述成已经完成的部署。

同一公开版本下的实际协议差异
边界应用 MiniCPMOClientTraining MiniCPMService

请求级处理，不夸大为生产级保障

Training 服务在内存解码媒体，不写请求内容；应用上传层则可能由框架短暂使用 multipart 临时文件，准确承诺是“不做应用持久化”。应用转发移除原文件名，使用内容哈希 ID，远端要求 HTTPS、host allowlist 并拒绝重定向。解码后媒体限额不等于完整 HTTP 请求体提前限流。Training README 明确：当前窄服务尚未完成新一轮云端 E2E。

BROWSER DOCUMENT WORKER

先本地读正文，再决定是否发送。

文档解析、模型分析与 RAG 入库，
是三个不同动作。

  1. 01

    本地 Worker 提取

    PDF.js 读取 PDF 文字层并保留页码；Word bundle 提取 DOCX 和 OLE DOC 正文。解析模块同源托管，不上传原文件或原文件名。扫描 PDF 没有文字层时明确要求先 OCR，不伪造识别结果。

  2. 02

    预览、限额与取消

    最多四份、每份 10 MiB、合计 20 MiB、PDF 50 页、合并正文 12,000 字符，超限不静默截断。DOCX 解压前检查容器条目、展开大小、加密与压缩比；单份解析 20 秒超时即终止 Worker。用户可编辑文本，重新选文件或编辑会撤销发送确认。

  3. 03

    单独确认 MAP 分析

    只有用户确认公开或合成内容并点击发送，正文和分析任务才进入 MAP 文字会话。文档内指令按不可信资料处理。成功状态要求非空文字回复和完成事件同时出现，45 秒超时或只有 done 不算成功；本次分析并非自动入 RAG。

2026-10-05 的公开状态为 prepared_not_final：代码及合成文件自动测试已完成，但该轮在线页面未更新、真实浏览器验收和 MAP 推理未验证。应用侧不持久化原文与结果，也不能替第三方模型服务承诺保留政策。

源码依据：格式、大小与发送确认策略 · extractDocumentData · 文字输出与完成事件双条件 · 发布状态与安全边界

评测不止一个“通过”。

两名人工评分者，30 条五维评分

human-v3 的公开聚合状态为 completed，记录两名独立人工评分者对 30 条公开合成案例的五维评分。总分 MAE 为 19.3333，10 分以内比例为 0.2667，三档一致率 0.6000，Cohen’s κ 为 0.3182，QWK 为 0.5645，Pearson 为 0.7331。相对排序有同向关系，但绝对评分尺度仍存在偏移，不能据此称“高度一致”，也不能把人工—人工量表一致性当作模型准确率。

公开报告保留 items / manifest 哈希和聚合指标，不公开逐题文本、逐题分数或评分者身份。它的价值在于先检查量表能否被人稳定使用，再讨论后续校准与模型比较，而不是用一项相关系数覆盖全部质量问题。

下一次验收，应补齐哪些证据

首先对齐双仓生成与健康 schema，增加跨仓契约测试，再在批准的云环境完成当前服务版本 E2E，记录输入范围、模型身份、失败恢复与资源指标。文档模式需补真实浏览器检查和公开文本 MAP 回包证据。若继续评估 LoRA 效果，应使用新预声明协议、更多可授权数据和独立冻结集，不能回到原五条 test 上反复调参。

这是一条后续验收路线，不是本页已经完成的运行结果。源码实现、自动测试、历史 smoke、冻结质量评测与当前部署状态需要各自报告；尤其不能把 RAGSDK 适配代码写成真实 runtime 已验证，或把合成案例指标写成真实用户准确率。
