实习经历 C 端多工具工作台 · 接入规范 · 成本归因

SeaMe AI 电商工具平台

面向商品图、短视频与智能体的多工具聚合平台。将平台交互、异常恢复与透明计费沉淀为 880 行可执行接入 Prompt，让新工具生成即合规、故障和费用可归因到具体工具与用户。

  • 个人职责：负责部分生成工具开发运维，梳理覆盖 image / video / agent / 3d / data / game 6 类工具的标准化接入 Prompt 与 7 项验收清单。
  • C 端交互决策：强制统一 Sticky 状态顶栏与「输入表单 → 2s 进度轮询 → 结果灯箱与 12h 会话恢复」三步面板，启动自动清理残留 running 任务。
  • 计费归因取舍：通过 httpx 透明代理与 vtrix_hook 拦截调用；异步任务 Phase 1 先记 Pending 预估费用、Phase 2 终态覆盖实际 USD，配四级计费兜底。

03 / HOW I MAKE AI PRODUCT DECISIONS

能把策略想清楚，
也能把系统接完整。

以工程实现与固定评测支撑产品判断，
点击展开每条原则对应的真实项目取舍。

01

先把问题收窄，用统一骨架降低 C 端与协作成本

场景定义 → 核心路径与规范化

明确用户核心任务、输入输出和失败恢复路径，先打通一条可闭环的主路径，再扩展多模态或外围能力。

项目实证：在 SeaMe 平台实习中，将 6 类工具的前端结构收束为「输入面板 → 2s 轮询进度 → 结果灯箱与 12h 历史会话恢复」三步骨架，并写成 880 行结构化接入 Prompt；在 CareerPilot 中先做文本 MVP 跑通「岗位诊断→证据匹配→追问训练」，再扩展多模态输入。

02

切分「模型生成」与「确定性规则/工程」的职责边界

Agent 编排 → 状态可控与防幻觉

不把所有事情都交给单次 Prompt：让 LLM 负责意图理解、追问组织和自然语言反馈；把计费归因、状态落库、冲突拦截和权限确认交给确定性代码与工作流。

项目实证：在 CareerPilot 中我负责除评测外的全部 Agent 编排，强制把无来源经历标记为「待补」禁止模型扩写，外部修改必须走 interrupt 人工确认；在 AIRI 中开发记忆审核台，先检查冲突再写入长期记忆；在 SeaMe 中用 httpx 透明代理与两阶段日志（Pending 预估 → 终态覆盖实付）解决异步计费漏记问题。

03

用固定评测集和诚实基线定位 Badcase，不把跑通当提效

回归评测 → 诚实汇报与下一次迭代

保留传统或 Base 基线、固定评测用例和失败样例。严格区分「界面演示」「链路 Smoke 跑通」与「模型质量真正提升」。

项目实证：在 CareerPilot 中配合 20 条固定合成用例复测方向漂移与单轮多题；在 GradLoop 昇腾实验中如实记录固定 5 例评测 LoRA 未获提升、保留 Base 模型；在 MultiModal-QC 中同时保留 ResNet/YOLO 分类基线与 Qwen2-VL 测试集（n=173）对照。

04 / EVIDENCE, NOT JUST FEATURES

产品判断，需要可复查的依据。

模型效果与基线对照
